# 《动物园和声》客户端状态机说明 v1

## 1. 文档目的

本文件用于定义《动物园和声》MVP 阶段的客户端状态机设计。

平台口径说明：

- 正文默认按 `TapTap Android 首发` 编写
- 状态机设计本身为平台无关逻辑
- 微信小游戏相关差异说明统一放在文末“微信小游戏适配参考”章节

本文档目标：

1. 统一客户端页面状态、业务状态和对局状态的边界
2. 明确不同模块间的状态切换关系
3. 为前端实现、联调和测试提供可执行的状态流定义
4. 降低对局过程中因状态混乱导致的 UI 和逻辑错误

## 2. 设计原则

1. 状态最小化：一个状态只表达一个明确阶段
2. 服务端权威：对局核心状态以服务端广播为准
3. 页面状态与业务状态分离：避免用页面展示替代真实状态
4. 可恢复：掉线、重连、结算未就绪等异常路径必须有明确状态
5. 可追踪：关键状态切换应可打印日志和埋点

## 3. 状态机分层

客户端状态建议拆成五层：

1. 全局应用状态机
2. 局外导航状态机
3. 匹配状态机
4. 对局状态机
5. 网络与重连状态机

## 4. 全局应用状态机

## 4.1 状态定义

全局应用状态建议定义为：

1. `bootstrapping`
2. `login_required`
3. `logging_in`
4. `loading_profile`
5. `tutorial_pending`
6. `lobby_ready`
7. `in_matchmaking`
8. `in_battle`
9. `in_result`
10. `fatal_error`

## 4.2 状态说明

### `bootstrapping`

含义：

- 应用启动中
- 正在加载本地资源、基础配置与静态卡牌配置

可进入来源：

1. App 冷启动
2. App 热启动后需要重新校验配置

可流向：

1. `login_required`
2. `fatal_error`

### `login_required`

含义：

- 等待用户完成登录

可流向：

1. `logging_in`

### `logging_in`

含义：

- 正在执行平台登录与服务端登录

可流向：

1. `loading_profile`
2. `login_required`
3. `fatal_error`

### `loading_profile`

含义：

- 正在拉取玩家资料、资源、当前牌库、赛季信息

可流向：

1. `tutorial_pending`
2. `lobby_ready`
3. `fatal_error`

### `tutorial_pending`

含义：

- 新用户待进入新手引导

可流向：

1. `lobby_ready`

### `lobby_ready`

含义：

- 局外主状态，允许访问大厅、构筑、抽卡、图鉴、段位等页面

可流向：

1. `in_matchmaking`
2. `fatal_error`

### `in_matchmaking`

含义：

- 已发起匹配，等待匹配成功或取消

可流向：

1. `lobby_ready`
2. `in_battle`
3. `fatal_error`

### `in_battle`

含义：

- 已进入实时对局

可流向：

1. `in_result`
2. `lobby_ready`
3. `fatal_error`

### `in_result`

含义：

- 对局已结束，展示结算结果

可流向：

1. `lobby_ready`
2. `in_matchmaking`

### `fatal_error`

含义：

- 无法继续当前流程的致命错误状态

可流向：

1. `login_required`
2. `bootstrapping`

## 4.3 全局状态切换示意

```text
bootstrapping
  -> login_required
  -> fatal_error

login_required
  -> logging_in

logging_in
  -> loading_profile
  -> login_required
  -> fatal_error

loading_profile
  -> tutorial_pending
  -> lobby_ready
  -> fatal_error

tutorial_pending
  -> lobby_ready

lobby_ready
  -> in_matchmaking
  -> fatal_error

in_matchmaking
  -> lobby_ready
  -> in_battle
  -> fatal_error

in_battle
  -> in_result
  -> lobby_ready
  -> fatal_error

in_result
  -> lobby_ready
  -> in_matchmaking
```

## 5. 局外导航状态机

全局进入 `lobby_ready` 后，页面层建议维护一个更轻量的局外导航状态：

1. `home`
2. `deck_builder`
3. `gacha`
4. `album`
5. `rank`
6. `mode_select`

### 状态切换原则

1. 大厅为局外默认根状态
2. 构筑、抽卡、图鉴、段位都可返回大厅
3. 对战模式选择从大厅进入，匹配成功后切到全局 `in_matchmaking`

### 局外导航切换图

```text
home
  <-> deck_builder
  <-> gacha
  <-> album
  <-> rank
  -> mode_select

mode_select
  -> home
  -> in_matchmaking
```

## 6. 匹配状态机

## 6.1 状态定义

匹配流程建议拆成：

1. `idle`
2. `validating_deck`
3. `queueing`
4. `matched`
5. `canceling`
6. `match_failed`

## 6.2 状态说明

### `idle`

含义：

- 未进入匹配

### `validating_deck`

含义：

- 点击开始匹配后，先在本地与服务端检查出战牌库是否合法

可流向：

1. `queueing`
2. `match_failed`
3. `idle`

### `queueing`

含义：

- 已进入匹配队列

UI 表现：

1. 显示匹配动画
2. 展示等待时间
3. 提供取消匹配按钮

可流向：

1. `matched`
2. `canceling`
3. `match_failed`

### `matched`

含义：

- 已匹配成功
- 正在跳转战斗场景或建立 WebSocket

可流向：

1. `in_battle`
2. `match_failed`

### `canceling`

含义：

- 用户点击取消，正在等待服务端确认

可流向：

1. `idle`
2. `queueing`

### `match_failed`

含义：

- 匹配流程失败

处理建议：

1. 弹出错误提示
2. 状态回到 `idle`

## 6.3 匹配触发事件

| 事件 | 来源 | 当前状态 | 下一个状态 |
|---|---|---|---|
| click_start_match | 用户点击匹配 | idle | validating_deck |
| deck_validated | 服务端返回合法 | validating_deck | queueing |
| deck_invalid | 服务端返回非法 | validating_deck | match_failed |
| matchmaking_success | 服务端匹配成功 | queueing | matched |
| click_cancel_match | 用户点击取消 | queueing | canceling |
| cancel_success | 服务端取消成功 | canceling | idle |
| match_error | 服务端匹配失败 | queueing / matched | match_failed |

## 7. 对局状态机

对局状态机是客户端最核心的状态机，建议拆成：

1. 房间生命周期状态
2. 当前回合归属状态
3. 当前步骤状态
4. 本地提交流程状态

## 7.1 房间生命周期状态

建议定义：

1. `initializing`
2. `joining`
3. `snapshot_ready`
4. `playing`
5. `ending`
6. `finished`
7. `result_loading`

### `initializing`

含义：

- 已从匹配成功页切入对局场景
- 正在准备页面资源和本地状态容器

### `joining`

含义：

- 已建立 WebSocket，正在发送 `match.join`

### `snapshot_ready`

含义：

- 已收到 `match.join_ack`
- 对局初始快照已可用

### `playing`

含义：

- 正常对局中

### `ending`

含义：

- 已收到 `match.end`
- 不再允许继续提交操作

### `finished`

含义：

- 对局逻辑已结束
- 客户端准备离开对局页

### `result_loading`

含义：

- 正在拉取对局结算结果

## 7.2 回合归属状态

建议定义：

1. `self_turn`
2. `opponent_turn`

状态来源：

1. `turn_player_id`
2. `self_player_id`

判定逻辑：

```text
if turn_player_id == self_player_id:
    self_turn
else:
    opponent_turn
```

### UI 影响

`self_turn`：

1. 中央市场可点击
2. 结束回合按钮可用
3. 当前步骤提示高亮

`opponent_turn`：

1. 交互禁用
2. 显示“等待对手操作”

## 7.3 当前步骤状态机

客户端显示层建议与服务端 `step_status` 对齐，定义如下：

1. `pick_terrain_group`
2. `place_terrain`
3. `optional_pick_card`
4. `optional_place_cube`
5. `ready_to_end_turn`

### 状态含义

#### `pick_terrain_group`

说明：

- 当前玩家需要从中央市场选择 1 组地形

允许操作：

1. 点击中央市场某组地形

禁止操作：

1. 放置地形
2. 拿动物牌
3. 结束回合

#### `place_terrain`

说明：

- 当前玩家已选地形组，必须完成 3 枚地形放置

允许操作：

1. 在版图上放置 3 枚地形

禁止操作：

1. 结束回合
2. 直接拿动物牌

#### `optional_pick_card`

说明：

- 3 枚地形已放完，可选从 4 张备选牌中拿 1 张

允许操作：

1. 点击备选牌加入进行中区域
2. 跳过拿牌
3. 进入动物方块放置
4. 结束回合

#### `optional_place_cube`

说明：

- 当前玩家可向进行中的动物牌放动物方块

允许操作：

1. 选择进行中牌
2. 点击版图合法位置放动物方块
3. 返回不放，直接结束回合

#### `ready_to_end_turn`

说明：

- 当前玩家本回合已无强制动作，可直接结束回合

允许操作：

1. 继续放动物方块
2. 结束回合

## 7.4 本地动作提交状态机

为了避免重复点击和脏状态，客户端本地每类动作建议再维护提交流程状态：

1. `idle`
2. `submitting`
3. `submitted_waiting_sync`
4. `failed`

适用动作：

1. 选择地形组
2. 放置地形
3. 选择动物牌
4. 放置动物方块
5. 结束回合

### 流程说明

`idle`：

- 尚未发起动作

`submitting`：

- 正在发送 WebSocket 请求

`submitted_waiting_sync`：

- 已收到 ack 或已提交成功，等待最新 `match.state_update`

`failed`：

- 收到 `match.error` 或超时失败

### 设计建议

1. 动作成功后，不要直接用本地结果覆盖全局状态
2. 应等待服务端广播的 `match.state_update`
3. 这样可以避免本地与服务端状态不一致

## 8. 对局状态组合关系

客户端对局页的有效状态，实际由多维状态组合决定：

1. 房间生命周期状态
2. 回合归属状态
3. 当前步骤状态
4. 网络状态

例如：

### 示例 1

- 房间状态：`playing`
- 回合归属：`self_turn`
- 步骤：`pick_terrain_group`
- 网络：`connected`

UI 表现：

1. 中央市场可选
2. 其他行动按钮禁用

### 示例 2

- 房间状态：`playing`
- 回合归属：`opponent_turn`
- 网络：`connected`

UI 表现：

1. 版图只读
2. 底部提示等待对手操作

### 示例 3

- 房间状态：`playing`
- 回合归属：`self_turn`
- 步骤：`optional_place_cube`
- 网络：`reconnecting`

UI 表现：

1. 全部主交互临时禁用
2. 出现重连遮罩

## 9. 网络与重连状态机

## 9.1 网络状态定义

建议定义：

1. `connected`
2. `unstable`
3. `reconnecting`
4. `reconnect_failed`

### `connected`

- WebSocket 正常连接

### `unstable`

- 心跳延迟变高或短时波动

### `reconnecting`

- 连接断开，客户端正在尝试恢复

### `reconnect_failed`

- 超过最大重试次数或服务端恢复失败

## 9.2 重连触发条件

满足以下条件之一时进入 `reconnecting`：

1. WebSocket onclose
2. 心跳超时
3. 发送动作后长期无响应且底层已断链

## 9.3 重连流程

```text
connected
  -> unstable
  -> reconnecting

reconnecting
  -> connected
  -> reconnect_failed
```

建议流程：

1. 显示重连遮罩
2. 停止新的本地交互
3. 重建 WebSocket
4. 再次发送 `match.join`，携带 `resume = true`
5. 收到恢复快照后恢复页面
6. 若恢复失败，退出对局并提示结果

## 10. 结算状态机

建议定义：

1. `waiting_match_end`
2. `result_pending`
3. `result_ready`
4. `reward_confirmed`
5. `leave_result`

### `waiting_match_end`

- 正常对局中，尚未收到结束事件

### `result_pending`

- 已收到 `match.end`
- 正在拉取结算接口

### `result_ready`

- 已拿到完整结果
- 可展示结算页

### `reward_confirmed`

- 奖励结果已展示并确认入账

### `leave_result`

- 用户离开结算页，回到大厅或再来一局

## 11. 构筑页状态机

构筑页建议维护独立状态：

1. `loading`
2. `editing`
3. `dirty`
4. `saving`
5. `save_failed`
6. `saved`

### 说明

`loading`：

- 正在加载卡池与当前牌库

`editing`：

- 当前可编辑，但无未保存变更

`dirty`：

- 用户修改过牌库，存在未保存改动

`saving`：

- 正在提交牌库保存请求

`save_failed`：

- 保存失败，需提示错误原因

`saved`：

- 已保存成功，可回到 `editing`

## 12. 抽卡页状态机

抽卡页建议维护：

1. `idle`
2. `drawing`
3. `result_popup`
4. `draw_failed`

### 说明

`idle`：

- 正常浏览卡池

`drawing`：

- 正在发起抽卡请求

`result_popup`：

- 抽卡结果弹窗展示中

`draw_failed`：

- 资源不足或接口失败

## 14. 客户端本地数据容器建议

为了让状态机清晰，建议客户端至少拆分以下状态容器：

1. `appStore`
2. `playerStore`
3. `deckStore`
4. `matchmakingStore`
5. `battleStore`
6. `resultStore`

### `appStore`

负责：

1. 全局应用状态
2. 登录态
3. 平台信息
4. 配置版本

### `playerStore`

负责：

1. 头像、昵称、资源
2. 当前段位
3. 当前出战牌库 ID

### `deckStore`

负责：

1. 已拥有卡牌
2. 牌库列表
3. 构筑编辑状态

### `matchmakingStore`

负责：

1. 当前匹配模式
2. 当前匹配状态
3. 排队时长

### `battleStore`

负责：

1. 房间生命周期状态
2. 当前回合归属
3. 步骤状态
4. 版图快照
5. 备选牌
6. 进行中动物牌
7. 网络状态

### `resultStore`

负责：

1. 结算状态
2. 结算结果
3. 奖励变化

## 15. 常见错误场景与状态处理

### 15.1 保存牌库失败

处理：

1. 构筑页状态切到 `save_failed`
2. 展示具体错误原因
3. 保留当前未保存编辑状态

### 15.2 匹配中网络失败

处理：

1. 匹配状态切到 `match_failed`
2. 返回模式选择页或大厅

### 15.3 对局中重复点击结束回合

处理：

1. 本地动作状态已在 `submitting` 或 `submitted_waiting_sync` 时禁用重复点击
2. 服务端若仍收到重复动作，由错误码 `5013` 兜底

### 15.4 对局中断线

处理：

1. 网络状态切到 `reconnecting`
2. 房间生命周期仍保持 `playing`
3. 恢复成功后继续
4. 恢复失败后转向 `ending` 或直接退出

### 15.5 结算接口长时间未返回

处理：

1. 结算状态保持 `result_pending`
2. 展示“结果生成中”
3. 超过阈值给重试提示

## 16. 测试验收重点

### 16.1 状态切换正确性

1. 冷启动到大厅流程完整
2. 新用户和老用户流转分支正确
3. 匹配取消后回到局外正确状态
4. 对局结束后能稳定进入结算页

### 16.2 对局状态正确性

1. 不是自己回合时不能操作
2. 不同步骤下按钮启用状态正确
3. 收到新的 `match.state_update` 后 UI 与状态同步

### 16.3 异常流正确性

1. 掉线重连后状态可恢复
2. 恢复失败后能退出脏状态
3. 结算未就绪时不会提前展示旧结果

## 17. 实现建议

1. 推荐使用显式枚举，不要用布尔值堆叠描述大状态
2. 关键状态切换统一走 action 或 reducer
3. WebSocket 事件处理层不要直接操作 UI 组件
4. 由状态层驱动 UI，而不是由 UI 直接推断业务状态

## 19. 微信小游戏适配参考

以下内容仅作为后续适配微信小游戏时的参考，不影响 TapTap Android 首发状态机主结构：

1. 全局应用状态机和对局状态机本身可保持不变。
2. 微信小游戏前后台切换更频繁，`reconnecting` 进入条件应更积极。
3. 若小游戏环境下 WebSocket 稳定性更弱，可提高 `result_pending` 和 `reconnecting` 的兜底提示频率。
