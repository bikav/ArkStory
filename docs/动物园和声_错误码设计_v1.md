# 《动物园和声》错误码设计 v1

## 1. 文档目的

本文件用于定义《动物园和声》MVP 阶段的统一错误码体系。

平台口径说明：

- 正文默认按 `TapTap Android 首发` 编写
- 错误码体系本身为平台无关设计
- 微信小游戏相关差异说明统一放在文末“微信小游戏适配参考”章节

设计目标：

1. 为 HTTP 接口和 WebSocket 事件提供统一错误码标准
2. 便于客户端提示文案、测试验收、日志检索和埋点统计
3. 保证错误码可扩展、可分层、可追踪
4. 避免不同模块重复占用相同错误码

## 2. 设计原则

1. 错误码按模块分段，便于定位问题来源
2. 一个错误码只表达一种主要错误语义
3. 错误码稳定，提示文案可调整但编号不轻易变更
4. 客户端展示文案与服务端内部原因可分离
5. 对局实时错误与大厅 HTTP 错误共用统一体系

## 3. 通用返回约定

HTTP 返回建议结构：

```json
{
  "code": 3002,
  "message": "deck cost exceeds limit",
  "data": {}
}
```

WebSocket 错误返回建议结构：

```json
{
  "event": "match.error",
  "request_id": "req_turn_001",
  "server_event_id": "sev_10020",
  "state_version": 8,
  "code": 5004,
  "message": "terrain placement invalid",
  "data": {
    "failed_event": "match.place_terrain",
    "retryable": false
  }
}
```

字段说明：

- `code`：错误码
- `message`：机器可读错误说明，推荐英文短语
- `data`：可选的补充字段

## 4. 错误码分段

MVP 先采用四位错误码，按模块预留如下：

- `1000-1999`：认证与会话
- `2000-2999`：玩家资源与通用业务
- `3000-3999`：卡牌、牌库与构筑
- `4000-4999`：匹配、房间与排位
- `5000-5999`：对局实时动作与状态
- `6000-6999`：结算、奖励与回放
- `7000-7999`：系统、配置与服务端内部错误

## 5. 错误等级建议

为了方便埋点和客户端处理，建议每个错误码额外记录一个错误等级：

- `info`：轻提示，不影响主流程
- `warning`：当前操作失败，但用户可重试
- `error`：当前操作失败，且通常需要用户调整行为
- `fatal`：严重错误，可能需要退出当前页面或中断对局

## 13. 典型映射关系

以下是当前文档中已出现的主要场景与推荐错误码映射：

### 13.1 登录与会话

- 登录凭证无效：`1005`
- access token 失效：`1002` 或 `1003`
- 对局房间 token 无效：`1010`

### 13.2 构筑与牌库

- 牌库张数不是 12：`3001`
- 构筑成本超过 24：`3002`
- 白卡少于 3 张：`3003`
- 红卡多于 2 张：`3004`
- 同名牌重复：`3005`
- 牌库中含未拥有卡牌：`3006`

### 13.3 匹配与房间

- 非法牌库尝试匹配：`4004`
- 已在匹配中又发起匹配：`4001`
- 已在其他房间中：`4005`

### 13.4 实时对局

- 非当前玩家出手：`5001`
- 当前步骤不允许该动作：`5002`
- 地形放置不合法：`5004`
- 选择不在备选区的动物牌：`5007`
- 进行中动物牌超过上限：`5008`
- 动物方块图案条件不成立：`5009`
- 回合没放完 3 枚地形就结束：`5012`
- 客户端重复提交同一动作：`5013`
- 客户端状态版本过旧：`5014`

### 13.5 结算与奖励

- 结算结果未准备好：`6001`
- 奖励发放失败：`6002`
- 分数校验不一致：`6007`

## 14. 客户端展示文案建议

建议前端不要直接显示 `message` 原文，而是按错误码映射本地化文案。

展示策略建议：

1. `warning`：使用轻提示
2. `error`：使用弹窗或就地提示
3. `fatal`：使用强提示并中断流程

示例：

- `3002`：当前牌库总成本超过上限 24，请调整后再保存
- `5008`：进行中的动物牌已满，先完成或结算已有动物牌
- `6001`：结算结果生成中，请稍后重试

## 15. 埋点与日志建议

建议服务端与客户端都记录以下维度：

- `code`
- `message`
- `module`
- `request_id`
- `player_id`
- `match_id`
- `deck_id`
- `client_version`
- `platform`
- `state_version`

这样可以支持：

1. 按模块统计高频错误
2. 快速定位某个对局的问题链路
3. 排查客户端版本兼容性问题

## 16. 版本管理建议

错误码一旦对外发布，应遵循以下规则：

1. 已使用错误码不随意改编号
2. 允许补充说明，不轻易改语义
3. 废弃错误码保留编号，不立即复用
4. 新模块优先使用预留号段扩展

## 19. 微信小游戏适配参考

以下内容仅作为后续适配微信小游戏时的参考，不影响 TapTap Android 首发错误码体系：

1. 错误码本身无需改动。
2. 认证相关的 `1005` 可映射到微信登录凭证校验失败场景。
3. 若新增微信平台专属分享、广告或关系链能力，建议优先在 `2000` 或 `7000` 段新增错误码，不要挤占现有对局号段。
