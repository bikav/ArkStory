# 《动物园和声》接口清单 v1

## 1. 文档目的

本文件用于定义《动物园和声》MVP 阶段的服务端接口清单。

平台口径说明：

- 正文默认按 `TapTap Android 首发` 编写
- 多平台共用同一套业务后端，平台差异主要集中在认证、支付和少量客户端能力层

适用发布形态：

- TapTap Android 版本

设计原则：

1. 两端共用同一套业务后端
2. 平台相关能力通过平台参数和适配层分流
3. 对局核心状态以服务端为准
4. 能用 HTTP 的场景不用长连接
5. 实时对局同步使用 WebSocket

## 2. 接口分层

MVP 接口按以下层次划分：

1. 认证与会话
2. 基础配置
3. 玩家主页与资源
4. 卡牌与图鉴
5. 牌库构筑
6. 抽卡
7. 匹配与房间
8. 对局实时同步
9. 结算与奖励
10. 排位与赛季

## 3. 通用约定

## 3.1 基础协议

- 协议：`HTTPS + JSON`
- 实时对局：`WSS + JSON`
- 字符编码：`UTF-8`
- 时间格式：`ISO 8601` 或服务端标准时间戳

## 3.2 公共请求头

建议公共请求头：

- `Authorization: Bearer <token>`
- `X-Platform: taptap_android`
- `X-Client-Version: 1.0.0`
- `X-Device-Id: <device_id>`

## 3.3 公共返回结构

建议统一返回结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

说明：

- `code = 0` 表示成功
- 非 0 表示业务错误
- 具体错误码后续单独整理

## 3.4 平台字段约定

由于本项目后续需要支持多平台，认证接口和支付接口必须带平台参数：

- `platform`: `taptap_android`

后端根据该字段决定：

1. 登录凭证校验方式
2. 渠道参数记录方式
3. 统计归因方式

## 4. 认证与会话接口

## 4.1 登录

`POST /api/v1/auth/login`

用途：

- TapTap 安卓版登录
- 首次注册或老账号登录

请求示例：

```json
{
  "platform": "taptap_android",
  "taptap_token": "tt_token_xxx",
  "device_id": "device_xxx",
  "client_version": "1.0.0"
}
```

返回字段：

- `player_id`
- `access_token`
- `refresh_token`
- `is_new_player`
- `platform`

## 4.2 刷新 token

`POST /api/v1/auth/refresh`

用途：

- 刷新访问令牌

## 4.3 登出

`POST /api/v1/auth/logout`

用途：

- 主动注销当前会话

## 5. 基础配置接口

## 5.1 获取基础配置

`GET /api/v1/config/bootstrap`

用途：

- 获取客户端启动所需配置

返回建议包含：

- 当前赛季信息
- 最低客户端版本
- 是否开启维护
- 卡池版本号
- 公告摘要

## 5.2 获取卡牌静态配置版本

`GET /api/v1/config/card-version`

用途：

- 判断客户端本地卡牌配置是否需要更新

返回建议包含：

- `card_config_version`
- `hash`
- `download_url`

## 6. 玩家主页与资源接口

## 6.1 获取玩家主页信息

`GET /api/v1/player/profile`

返回建议包含：

- `player_id`
- `nickname`
- `avatar_url`
- `selected_deck_id`
- `rank_info`
- `resource_summary`
- `match_summary`

## 6.2 更新展示信息

`POST /api/v1/player/profile/update`

请求字段：

- `nickname`
- `avatar_url`
- `signature`

## 6.3 获取资源信息

`GET /api/v1/player/resources`

返回建议包含：

- `gold_coin`
- `gem`
- `card_shard`

## 6.4 获取资源流水

`GET /api/v1/player/resources/logs`

查询参数：

- `resource_type`
- `page`
- `page_size`

## 7. 卡牌与图鉴接口

## 7.1 获取玩家持卡列表

`GET /api/v1/cards/inventory`

查询参数：

- `rarity_color`
- `tag`
- `owned_only`
- `page`
- `page_size`

返回建议包含：

- `card_id`
- `owned_count`
- `is_owned`

## 7.2 获取单张卡牌详情

`GET /api/v1/cards/{card_id}`

用途：

- 获取单卡静态信息和玩家拥有情况

## 7.3 获取图鉴总览

`GET /api/v1/cards/album`

返回建议包含：

- 已解锁数量
- 各颜色解锁数量
- 各标签解锁数量

## 8. 牌库构筑接口

## 8.1 获取牌库列表

`GET /api/v1/decks`

返回建议包含：

- 牌库 ID
- 牌库名
- 是否当前出战
- 总成本
- 白蓝金红数量
- 是否合法

## 8.2 获取单个牌库详情

`GET /api/v1/decks/{deck_id}`

返回建议包含：

- 牌库基本信息
- 12 张卡牌列表
- 成本统计
- 规则校验结果

## 8.3 新建牌库

`POST /api/v1/decks`

请求字段：

```json
{
  "deck_name": "山树中速"
}
```

## 8.4 更新牌库卡牌

`PUT /api/v1/decks/{deck_id}`

请求字段：

```json
{
  "deck_name": "山树中速",
  "card_ids": ["W01", "W04", "W06", "W09", "W11", "B01", "B02", "B06", "B10", "G01", "G02", "R01"]
}
```

服务端校验：

1. 必须恰好 12 张
2. 同名牌最多 1 张
3. 总成本不超过 24
4. 白色至少 3 张
5. 红色最多 2 张
6. 玩家必须拥有所有卡牌

返回建议包含：

- `is_valid`
- `validation_errors`
- `cost_summary`

## 8.5 删除牌库

`DELETE /api/v1/decks/{deck_id}`

限制：

- 当前出战牌库不可直接删除，需先切换

## 8.6 设置当前出战牌库

`POST /api/v1/decks/{deck_id}/select`

## 9. 抽卡接口

## 9.1 获取卡包列表

`GET /api/v1/gacha/pools`

返回建议包含：

- 卡包 ID
- 卡包名称
- 消耗类型
- 消耗数量
- 可产出范围
- 当前是否开放

## 9.2 执行抽卡

`POST /api/v1/gacha/draw`

请求示例：

```json
{
  "pool_id": "normal_pool_001",
  "draw_count": 1
}
```

返回建议包含：

- 本次消耗
- 本次获得卡牌列表
- 抽卡后资源余额

服务端要求：

- 记录 `gacha_log`
- 记录 `reward_log`
- 处理重复卡转化逻辑

## 9.3 获取抽卡日志

`GET /api/v1/gacha/logs`

## 10. 匹配与房间接口

## 10.1 开始匹配

`POST /api/v1/matchmaking/start`

请求字段：

```json
{
  "match_type": "ranked",
  "deck_id": 10001
}
```

服务端校验：

1. 牌库存在
2. 牌库属于当前玩家
3. 牌库合法
4. 玩家当前不在其他房间中

返回建议包含：

- `queue_id`
- `match_type`
- `estimated_wait_seconds`

## 10.2 取消匹配

`POST /api/v1/matchmaking/cancel`

## 10.3 查询匹配状态

`GET /api/v1/matchmaking/status`

返回状态示例：

- `matching`
- `matched`
- `cancelled`

若已匹配成功，返回：

- `match_id`
- `room_token`

## 10.4 好友房创建

`POST /api/v1/rooms/friend/create`

## 10.5 好友房加入

`POST /api/v1/rooms/friend/join`

## 11. 对局实时同步接口

MVP 对局建议使用 WebSocket。

连接方式：

`WSS /ws/v1/match?match_id=xxx&token=xxx`

## 11.1 客户端连接后首包

事件名：`match.join`

请求示例：

```json
{
  "event": "match.join",
  "data": {
    "match_id": 90001
  }
}
```

服务端返回：

- 当前房间信息
- 双方基础信息
- 是否轮到当前玩家
- 初始 4 张备选牌
- 初始中央地形市场

## 11.2 选择地形组

事件名：`match.pick_terrain_group`

请求字段：

- `group_index`

## 11.3 放置地形

事件名：`match.place_terrain`

请求字段：

```json
{
  "placements": [
    {"piece_index": 0, "q": 3, "r": 4, "stack_to": 0},
    {"piece_index": 1, "q": 4, "r": 4, "stack_to": 1},
    {"piece_index": 2, "q": 5, "r": 4, "stack_to": 0}
  ]
}
```

说明：

- `stack_to` 表示叠放层级参考值，具体实现可按项目实际调整

## 11.4 选择动物牌

事件名：`match.pick_animal_card`

请求字段：

- `card_id`

限制：

- 必须来自当前 4 张备选牌
- 进行中动物牌未满 4 张

## 11.5 放置动物方块

事件名：`match.place_animal_cube`

请求字段：

```json
{
  "card_id": "W01",
  "placement_q": 2,
  "placement_r": 3
}
```

服务端需校验：

1. 对应图案是否成立
2. 落点是否为空
3. 该卡是否还有剩余方块槽位

## 11.6 结束回合

事件名：`match.end_turn`

作用：

- 明确回合提交点
- 触发服务端补地形组
- 若本回合拿过动物牌，补 1 张备选牌

## 11.7 状态广播

服务端广播事件建议包括：

- `match.state_update`
- `match.turn_change`
- `match.error`
- `match.end`

## 12. 结算与奖励接口

## 12.1 获取对局结果

`GET /api/v1/matches/{match_id}/result`

返回建议包含：

- 双方总分
- 地形分
- 动物牌分
- 已放置动物方块数
- 胜负结果
- 金币奖励
- 星级变化

## 12.2 获取对局简报

`GET /api/v1/matches/{match_id}/summary`

用途：

- 结算页轻量展示

## 12.3 获取对局日志或回放数据

`GET /api/v1/matches/{match_id}/replay`

返回建议包含：

- `match_room`
- `match_player`
- `match_action_log`
- `match_result`

## 14. 推荐错误码分组

建议至少预留以下错误码段：

- `1000-1999`：认证相关
- `2000-2999`：资源相关
- `3000-3999`：构筑相关
- `4000-4999`：匹配相关
- `5000-5999`：对局动作相关
- `6000-6999`：结算相关

典型错误示例：

- `3001`：牌库张数不合法
- `3002`：牌库成本超限
- `3003`：白色卡牌不足
- `3004`：红色卡牌超限
- `5001`：地形放置非法
- `5002`：动物牌不在备选区
- `5003`：进行中动物牌已满
- `5004`：动物方块放置条件不满足

## 15. 接口优先级

## 15.1 P0

必须先做：

1. 登录
2. 获取主页
3. 获取持卡列表
4. 获取牌库列表与详情
5. 更新牌库
6. 开始匹配 / 取消匹配 / 查询匹配状态
7. WebSocket 对局实时接口
8. 获取对局结果
9. 获取当前段位

## 15.2 P1

可第二阶段接入：

1. 抽卡
2. 抽卡日志
3. 对局回放
4. 排行榜
5. 资源流水

## 16. 跨平台注意点

由于后续需要扩展多平台，接口层必须注意：

1. 登录凭证结构不同
2. 支付回调来源不同
3. 分享和社交能力不通过通用后端强耦合
4. 不在业务接口层写死渠道专属字段

正确做法是：

- 业务接口统一
- 平台认证单独分流
- 平台 SDK 能力由客户端适配层处理

## 18. 微信小游戏适配参考

以下内容仅作为后续适配微信小游戏时的接口参考，不影响 TapTap Android 首发接口主流程：

### 18.1 登录示例

微信小游戏登录请求示例：

```json
{
  "platform": "wechat_game",
  "login_code": "wx_login_code",
  "device_id": "device_xxx",
  "client_version": "1.0.0"
}
```

### 18.2 适配说明

1. 微信小游戏登录依赖微信登录凭证换取平台身份。
2. 微信支付、广告、分享等能力不建议直接揉进通用业务接口。
3. 若后续新增微信专属接口，建议统一归类到渠道适配层，而不是改写核心业务路径。
