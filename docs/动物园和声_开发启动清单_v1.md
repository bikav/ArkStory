# 《动物园和声》开发启动清单 v1

## 1. 文档目的

本文件用于给《动物园和声》项目提供正式开工前的开发启动清单。

平台口径说明：

- 正文默认按 `TapTap Android 首发` 编写
- 开发启动流程优先围绕 `Cocos Creator + TypeScript + Android` 展开
- 微信小游戏相关保留项统一放在文末“微信小游戏适配参考”章节

本文档目标：

1. 帮助项目从文档阶段切换到实际开发阶段
2. 明确环境安装顺序
3. 明确项目初始化步骤
4. 明确第一阶段的实际开发优先级
5. 避免一开工就陷入过早做后端、商业化和复杂系统的误区

## 2. 当前建议结论

如果你现在准备正式制作本项目，建议按以下顺序启动：

1. 安装 `Cocos Dashboard`
2. 安装稳定版 `Cocos Creator`
3. 安装 `Node.js`
4. 安装 `Git`
5. 安装 `Android Studio`
6. 安装 `JDK`
7. 创建 Cocos 项目
8. 先做 `可运行对局原型`
9. 再逐步接入构筑、抽卡、匹配与服务端

一句话原则：

`先跑通核心对局原型，再补外围系统。`

## 3. 技术路线建议

## 3.1 客户端

建议使用：

- 引擎：`Cocos Creator`
- 语言：`TypeScript`
- 首发平台：`Android`
- 后续平台：`微信小游戏`

原因：

1. 你的项目是 `2D + 棋盘 + UI驱动 + 轻实时对战`
2. Cocos 对这类项目足够成熟
3. 后续兼容微信小游戏路径较顺
4. TypeScript 对中型逻辑项目更适合长期维护

## 3.2 服务端

启动阶段建议采用两段式：

1. `阶段一`：本地假数据 + 单机规则验证
2. `阶段二`：接真实服务端和 WebSocket

原因：

1. 目前你最先需要验证的是玩法，不是后台
2. 过早进入全链路开发，会放慢原型验证速度

## 3.3 版本策略

建议先做：

- `原型版 Prototype`
- `MVP 版`

而不是直接做“完整商业版本”。

## 4. 推荐安装清单

## 4.1 必装软件

### 1. Cocos Dashboard

用途：

1. 管理 Creator 版本
2. 创建项目
3. 管理本地工程

### 2. Cocos Creator

版本建议：

- `3.8 LTS` 或当前稳定 `3.8.x`

不建议：

- 一开始就用测试版
- 一开始就追最新小版本而不考虑稳定性

### 3. Node.js

用途：

1. 项目脚本
2. 工具链运行
3. 依赖管理

建议版本：

- `Node 18 LTS` 或更稳定的当前 LTS

### 4. Git

用途：

1. 版本管理
2. 分支协作
3. 备份关键节点

### 5. Android Studio

用途：

1. Android SDK
2. 模拟器
3. 真机调试环境
4. 最终 Android 构建支持

### 6. JDK

建议：

- 使用与 Cocos Creator 当前 Android 构建链兼容的稳定版本
- 不要随意混装多个版本后不配置环境变量

## 4.2 推荐安装的软件

### 1. VS Code

用途：

1. TypeScript 开发
2. 文档管理
3. Git 集成

### 2. 图像工具

例如：

- Figma
- Photoshop
- Photopea

用途：

1. UI 原型
2. 切图
3. 临时占位图制作

### 3. 数据表工具

例如：

- Excel
- Notion

用途：

1. 卡牌池维护

3. 版本清单管理

## 5. 安装顺序建议

建议按下面顺序安装，避免互相依赖时返工：

1. `Git`
2. `Node.js`
3. `Cocos Dashboard`
4. `Cocos Creator`
5. `Android Studio`
6. `JDK`
7. 配置 Android 构建环境

原因：

1. Git 和 Node 最基础
2. Cocos 先能打开和创建项目
3. Android 环境后接即可

## 6. 项目初始化清单

## 6.1 先做这些事

1. 新建 git 仓库
2. 创建 Cocos 项目
3. 确认 TypeScript 可正常编译
4. 建立基础目录结构
5. 创建最小场景链路
6. 能在编辑器内预览
7. 能导出 Android 测试包或至少完成 Android 环境检测

## 6.2 项目命名建议

建议工程目录名使用英文或拼音，避免后续某些工具链对中文路径不稳定。

例如：

- `zoo-harmony-client`

显示名称仍可使用中文：

- `动物园和声`

## 6.3 版本库初始化建议

建议一开始就做：

1. 初始化 `git`
2. 添加 `.gitignore`
3. 提交第一次空项目

首批提交建议：

1. `init: create cocos project`
2. `chore: setup project structure`
3. `feat: add first playable board prototype`

## 7. 推荐目录结构

客户端目录建议尽快统一，不要边做边随意扩散。

```text
assets/
  scenes/
  scripts/
    core/
    config/
    data/
    managers/
    modules/
      battle/
      deck/
      gacha/
      lobby/
      result/
    ui/
      common/
      pages/
      popups/
    utils/
  resources/
    images/
    prefabs/
    fonts/
    audio/
docs/
tools/
```

### 7.1 目录职责建议

`scenes/`

- 放大厅、对局、结算等主场景

`scripts/core/`

- 放应用入口、状态机基础设施、事件总线等

`scripts/config/`

- 放本地静态配置读取逻辑

`scripts/data/`

- 放数据结构定义和 mock 数据

`scripts/managers/`

- 放资源、音频、网络、场景切换等全局管理器

`scripts/modules/`

- 按功能模块拆分业务逻辑

`scripts/ui/`

- 页面组件、公共组件、弹窗

## 8. 第一个里程碑建议

建议把开发拆成四个很明确的阶段。

### 阶段 1：空壳跑通

目标：

1. 能启动项目
2. 能切场景
3. 有大厅页
4. 有对局空场景
5. 有结算空场景

验收标准：

1. 点击大厅按钮能进入对局页
2. 点击按钮能从对局页进入结算页

### 阶段 2：核心棋盘原型

目标：

1. 六边形棋盘显示
2. 可选择地形组
3. 可在棋盘合法位置放地形
4. 基础回合流转

验收标准：

1. 本地单机完成一整回合
2. 能看到中央地形市场变化

### 阶段 3：动物牌原型

目标：

1. 12 张牌库本地加载
2. 开局随机洗牌并发 4 张备选牌
3. 从 4 张备选牌中选 1 张进入进行中区域
4. 能在满足图案条件时放动物方块
5. 能计算基础分数

验收标准：

1. 单机完成一局
2. 正确触发终局与结算

### 阶段 4：局外系统接入

目标：

1. 构筑页
2. 抽卡页
3. 图鉴页
4. 结算页正式化

验收标准：

1. 从大厅进入构筑与抽卡
2. 本地伪数据能驱动完整循环

## 10. 第一版先做什么，不先做什么

## 10.1 应该先做

1. 六边形棋盘
2. 地形放置
3. 回合流转
4. 备选动物牌逻辑
5. 动物方块落点验证
6. 本地结算

## 10.2 不要先做

1. 完整 TapTap 登录
2. 完整服务端
3. 完整 WebSocket
4. 完整抽卡概率系统
5. 美术精修
6. 商业化接入
7. 微信小游戏适配

原因：

这些内容都不影响你验证“游戏到底好不好玩”。

## 11. 原型阶段建议使用假数据

建议在原型阶段准备以下本地 mock 数据：

1. 32 张首发动物牌本地 JSON
2. 12 张固定测试牌库
3. 固定地形袋或伪随机地形组
4. 固定结算样例

建议先做：

1. 单人双端伪对战
2. 或单机双方面板切换

而不是一上来就做真实联网。

## 12. Cocos 项目初始化建议

## 12.1 推荐初始场景

建议至少建立以下场景：

1. `BootScene`
2. `LoginScene`
3. `LobbyScene`
4. `BattleScene`
5. `ResultScene`

## 12.2 推荐初始脚本

建议尽快建立这些基础脚本：

1. `App.ts`
2. `SceneRouter.ts`
3. `ConfigManager.ts`
4. `MockDataManager.ts`
5. `BattleStateStore.ts`
6. `DeckStore.ts`
7. `UIToast.ts`

## 12.3 推荐先跑的能力

1. 场景切换
2. 配置读取
3. 基础状态容器
4. 弹窗系统
5. 简单按钮事件

## 13. Android 启动建议

虽然首发目标是 Android，但启动阶段建议：

1. 先用 `Web Preview` 快速验证
2. 功能成型后再打 Android 包

原因：

1. Web 预览调试更快
2. 逻辑迭代效率更高
3. Android 构建放在功能稳定后更省时间

但要尽早确认：

1. Android 构建环境是通的
2. 真机包至少能成功打一次

## 15. 建议的实际开工顺序

你可以严格按下面顺序做：

1. 装环境
2. 建 Cocos 空工程
3. 搭目录和基础场景
4. 做大厅和切场景
5. 做棋盘和地形市场
6. 做本地回合流
7. 做动物牌与方块放置
8. 做本地结算
9. 做构筑页
10. 做抽卡页
11. 最后再接真实网络

## 16. 典型误区

### 误区 1

一开始就想把登录、支付、匹配、实时对战全部接完。

问题：

1. 节奏过重
2. 原型验证过慢

### 误区 2

一开始就纠结美术风格和高级特效。

问题：

1. 消耗大量时间
2. 核心玩法还没被验证

### 误区 3

一开始就追求“完美架构”。

问题：

1. 很容易空转
2. 迟迟没有第一版可玩内容

## 17. MVP 启动验收标准

你可以把“正式开工成功”定义为下面这几条全部满足：

1. Cocos 项目可打开
2. TypeScript 正常编译
3. 大厅页能打开
4. 对局空场景能打开
5. 六边形棋盘能渲染
6. 地形组能显示
7. 可以完成 1 个本地回合

做到这一步，项目就算真正启动了。
