# 《动物园和声》UI线框说明 v1

## 1. 文档目的

本文件用于定义《动物园和声》MVP 阶段的页面线框结构与布局说明。

平台口径说明：

- 正文默认按 `TapTap Android 首发` 编写
- 线框说明以移动端竖屏体验为主
- 微信小游戏相关差异说明统一放在文末“微信小游戏适配参考”章节

本文档目标：

1. 为 UI 设计提供页面骨架和信息层级
2. 为前端提供组件分区与布局参考
3. 为产品和研发统一关键页面的交互预期

## 2. 设计原则

1. 优先保证信息清晰，避免一次塞入过多规则文本
2. 核心主流程入口保持固定，减少跳转负担
3. 对局页优先保证操作效率，其次再做装饰表现
4. 构筑页优先保证筛选效率和合法性反馈
5. 结算页优先突出胜负、分数和奖励变化

## 3. 线框约定

本文档中的线框为低保真结构草图，仅表达：

1. 页面区块层级
2. 核心信息位置
3. 主要按钮位置
4. 页面滚动方向

不表达：

1. 最终视觉风格
2. 具体颜色与插画
3. 精细动画效果

常用标记：

- `[按钮]`：可点击按钮
- `(信息)`：静态信息
- `{列表}`：可滚动内容
- `<浮层>`：弹窗或覆盖层

## 4. 全局导航建议

MVP 建议采用“大厅聚合 + 页面跳转”模式，不做复杂底部 Tab。

主导航关系：

1. 登录页 -> 新手引导 / 大厅
2. 大厅 -> 对战模式选择
3. 大厅 -> 构筑页
4. 大厅 -> 抽卡页
5. 大厅 -> 图鉴页
6. 大厅 -> 段位页
7. 对战模式选择 -> 匹配中页 -> 对局页 -> 结算页 -> 大厅 / 再来一局

## 5. 登录页线框

### 5.1 页面结构

```text
+--------------------------------------------------+
|                    游戏 Logo                      |
|                                                  |
|               (副标题 / 版本信息)                |
|                                                  |
|                 [TapTap 登录]                    |
|                                                  |
|            [用户协议]   [隐私协议]               |
|                                                  |
|            (公告 / 维护提示 / 错误提示)          |
+--------------------------------------------------+
```

### 5.2 组件说明

1. `Logo 区`：展示品牌识别
2. `登录按钮`：主 CTA，页面唯一核心操作
3. `协议区`：放在登录按钮下方，默认勾选或显式勾选
4. `提示区`：用于显示维护、登录失败、配置错误

### 5.3 交互重点

1. 登录按钮点击后进入加载态
2. 若协议未勾选，则先提示勾选
3. 登录失败时，错误提示不应遮挡主按钮

## 7. 大厅首页线框

### 7.1 页面结构

```text
+--------------------------------------------------+
| (头像) 昵称             金币 宝石 碎片           |
|--------------------------------------------------|
|              (当前段位 / 星数 / 赛季)            |
|--------------------------------------------------|
|              (当前出战牌库信息卡)                |
|   牌库名 / 成本 / 白红数量 / 是否合法            |
|                 [去构筑]                         |
|--------------------------------------------------|
|                 [开始对战]                       |
|--------------------------------------------------|
|   [牌库构筑]   [抽卡]   [图鉴]   [段位]          |
|--------------------------------------------------|
|            {公告 / 活动 / 新手任务轻入口}        |
+--------------------------------------------------+
```

### 7.2 组件说明

1. `顶部资源条`：固定在上方，进入所有局外页面都尽量一致
2. `段位卡`：突出当前赛季与升星状态
3. `出战牌库卡`：必须给出合法性反馈
4. `开始对战`：大厅最强主按钮
5. `功能入口区`：四个次级入口

### 7.3 交互重点

1. 当前牌库非法时，`开始对战`置灰
2. 点击牌库卡可直接进入构筑页
3. 大厅应保留足够空间让“开始对战”成为唯一主视觉焦点

## 10. 构筑页线框

### 10.1 页面结构

```text
+--------------------------------------------------+
| [返回]                  牌库构筑                 |
|--------------------------------------------------|
| [牌库1▼]  成本 18/24  白 4  红 1  (合法)       |
| [保存] [设为出战] [新建牌库]                    |
|--------------------------------------------------|
| [全部] [白] [蓝] [金] [红] [标签] [搜索]        |
|--------------------------------------------------|
| {卡牌池滚动区}                                  |
|  ┌卡牌┐ ┌卡牌┐ ┌卡牌┐ ┌卡牌┐                    |
|  └----┘ └----┘ └----┘ └----┘                    |
|  ┌卡牌┐ ┌卡牌┐ ┌卡牌┐ ┌卡牌┐                    |
|  └----┘ └----┘ └----┘ └----┘                    |
|--------------------------------------------------|
| 当前牌库 12/12                                   |
| [01] [02] [03] [04] [05] [06]                   |
| [07] [08] [09] [10] [11] [12]                   |
|--------------------------------------------------|
| (非法原因提示区)                                 |
+--------------------------------------------------+
```

### 10.2 组件说明

1. `牌库信息条`：始终固定在顶部，实时展示合法性
2. `筛选条`：应常驻，方便快速筛选
3. `卡牌池`：可滚动网格列表
4. `当前牌库`：固定 12 槽，最好常驻底部或侧边
5. `非法原因提示区`：展示具体规则缺失项

### 10.3 交互重点

1. 卡牌加入时应即时更新成本和颜色统计
2. 若卡牌已在牌库中，应有“已选”态
3. 点击牌库中的卡牌可移除
4. 长按或点击卡牌可查看详情

### 16.1 页面结构总览

```text
+--------------------------------------------------+

|--------------------------------------------------|
| 中央地形市场                                     |

|--------------------------------------------------|
| 己方备选牌区                                     |
| [卡1] [卡2] [卡3] [卡4]                          |
|--------------------------------------------------|
| 己方进行中动物区                                 |
| [进行中1] [进行中2] [进行中3] [进行中4]          |
|--------------------------------------------------|
| 步骤提示：请选择1组地形                          |
| [结束回合]                      [投降]           |
+--------------------------------------------------+
```

### 16.2 顶部信息区说明

包含：

1. 对手头像与昵称
2. 当前回合数
3. 当前回合倒计时
4. 网络状态图标

### 16.3 中央地形市场说明

每组地形应包含：

1. 3 枚 token 缩略展示
2. 可选态
3. 已选态
4. 不可选态

### 16.4 己方版图区说明

版图区是页面中心主操作区，应占最大视觉面积。

要求：

1. 支持缩放与拖动
2. 放地形时高亮合法位置
3. 放动物方块时高亮合法落点
4. 已放置元素层级清晰

### 16.5 备选牌区说明

展示当前 `4 张`备选牌。

单张卡简化信息建议包含：

1. 名称
2. 颜色
3. 当前分值序列缩略
4. 是否可选

### 16.6 进行中动物区说明

展示最多 `4 张`进行中的动物牌。

单张卡展示：

1. 名称
2. 已放方块数
3. 最大槽位数
4. 当前预估得分

### 16.7 操作流线建议

当前玩家一回合的理想操作流线：

1. 先看中央地形市场
2. 再在版图中放置 3 枚地形
3. 选择是否从备选牌区拿牌
4. 再查看进行中动物区并完成图案
5. 最后点击结束回合

因此页面布局必须保持这条流线尽量顺手。

## 18. 弹窗与通用组件建议

### 18.1 通用确认弹窗

适用场景：

1. 退出对局确认
2. 投降确认
3. 删除牌库确认

结构建议：

```text
+----------------------------------------------+
|                 <确认弹窗>                   |
|        确定要执行该操作吗？                  |
|        [取消]         [确认]                |
+----------------------------------------------+
```

### 18.2 错误提示条

适用场景：

1. 构筑非法
2. 资源不足
3. 网络错误

建议：

1. 轻错误使用顶部 toast
2. 阻断错误使用中部弹窗

### 18.3 加载浮层

适用场景：

1. 登录中
2. 匹配中转场
3. 结算结果生成中

## 19. 响应式与适配建议

虽然首发以移动端竖屏为主，但仍建议注意以下适配：

1. 小屏手机上，对局页的版图区优先级最高
2. 备选牌区和进行中区可适当压缩高度
3. 对局页顶部信息尽量单行，不要堆太多字段
4. 构筑页在小屏上可采用上下布局，不强求左右布局

## 20. MVP 视觉优先级建议

若 UI 时间有限，优先保证以下页面：

1. 对局页
2. 构筑页
3. 大厅首页
4. 结算页
5. 登录页

抽卡、图鉴和段位页可以在首版使用较简洁的视觉模板。

## 23. 微信小游戏适配参考

以下内容仅作为后续适配微信小游戏时的参考，不影响 TapTap Android 首发线框主结构：

1. 大部分线框结构可直接复用。

4. 抽卡与公告入口在微信版本中可视情况进一步轻量化。
